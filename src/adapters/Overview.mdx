# Adapters

`adapters` is the second half of the ABI. `config` is what a component **is**; adapters are how it
**talks to the world**. A component never imports a data layer, a router or a fetch — it calls what
it was handed, and the app decides what that is.

```tsx
<RecordList config={jobsConfig} adapters={{ records }} />
```

That makes the adapters the architecture. There are six, they are small on purpose, and each one
below is a page of its own: what it is for, every method with what an implementation has to
guarantee and what it rejects with, the in-memory fake to reach for in stories and tests, and the
components that take it.

<AdapterList links={storybookLinks} />

**Config is generated by the agent, adapters are wired by the app.** Two failure modes, kept apart:
a wrong config renders a loud error card naming the field, and a wrong adapter is a wiring bug in
one file — the showcase puts all of its in `showcase/src/adapters.ts`, and that is the only file
there that knows an adapter exists.

**One instance serves every component that takes it.** `Records` handed to a list and to a form is
what makes a ticket saved on one screen appear on the other; neither component knows the other is
there. `subscribe` is what carries it.

**Every fake is real enough to run the failure path.** `fakeRecords` really enforces
`expectedVersion` and really throws `VersionConflictError`; `fakeFiles` really reports upload
progress and really refuses one file by name; `fakeChat` really streams a reply token by token.
Stories and tests run those paths with no backend and no network.
